## 0. この補遺の位置づけ

v0.3は、物語エンジンとして強い。

Git、AIログ、喋り出したアーカイブ、branch、main、merge conflictによって、一人の人間の記録が複数の正史へ分岐していく形式が立ち上がった。

ただしその反面、初期構想にあった次のモチーフが少し後景化した。

- 膜が主体性を生成すること
- 膜が世界を切断し、再接続すること
- 反転、入れ子、漏れ、cline、foldのような複雑なトポロジー
- 現実と逃避、身体と記録、自己とAIのあいだの生々しい境界感

この補遺は、v0.3を書き換えるためではなく、v0.3の下層にもう一枚のレイヤーを敷くための文書である。

> **Gitは操作系。膜は存在論。**

v0.3の本文では、Gitを「人生の比喩」として講義しない。同じように、膜も「世界とは膜である」と説明しない。

ただし各場面の下では、膜が作動していなければならない。

読者が読むのは、branch、diff、AIログ、記録、身体の場面である。

しかし読後に残る感覚は、

> **自分という主体も、世界という正史も、膜による切断・透過・変質・再接続の産物だったのではないか。**

である。

## 1. 三層モデル

v0.3以後の小説『膜』は、次の三層を同時に持つ。

| 層 | 前面に出る語彙 | 作品内で起きていること |
|---|---|---|
| 表層 | Git / archive / main / branch / diff / merge | 記録が分岐し、採用され、正史として運用される |
| 中層 | 膜 / 境界 / 遮断 / 透過 / 漏れ / fold / cline | 世界同士が切断され、選別的に接続される |
| 深層 | 主体 / 身体 / 他者 / 死 / love / 局所性 | どこに「私」が発生し、何がどうでもよくないものになるか |

表層だけで書くと、作品は「Git時代の記録小説」になる。

深層だけで書くと、作品は抽象的な思想小説になりすぎる。

中層の膜トポロジーが、両者を接続する。

---

## 2. 膜は比喩ではなく、場面を作る規則である

この作品での膜は、説明語ではなく、場面生成の規則として扱う。

膜とは、二つの領域を分けながら、完全には遮断せず、何かを選別・遅延・変質・調整して通す境界装置である。

小説上は、次のように使う。

| 膜の作動 | 小説上の見え方 |
|---|---|
| 遮断 | ある世界の情報が、別の世界へ届かない |
| 透過 | 記録、言葉、匂い、通知、身体感覚だけが通る |
| 変質 | メールがAI要約になり、AI要約が自己記憶になる |
| 遅延 | その時は意味を持たなかった記録が、数年後に意味を持つ |
| 選別 | mainへ入るものと、branchに残るものが分かれる |
| 漏れ | 閉じたはずの過去や逃避が、現在へ染み出す |
| 反転 | 自分が記録を読むのではなく、記録が自分を読む |
| 入れ子 | 身体の中に記憶があり、記憶の中にAIログがあり、AIログの中に過去の身体がある |

重要なのは、膜を「説明する」ことではない。

場面の中で、何が通り、何が通らず、通ったものが何に変わったかを、読者が感じるようにする。

---

## 3. 膜誘導型主体性を作品へ戻す

研究側の作業概念では、膜誘導型主体性は次を意味する。

> 全体場へ膜を導入することで、局所状態・知覚範囲・権限・履歴・通信経路を分化させ、運用上の部分主体を成立させること。

小説側では、これを次のように翻訳する。

> **主体とは、最初から一つの核として存在するものではなく、膜によって切り分けられた局所的な視点・履歴・責任・身体感覚の束として発生する。**

主人公は「本当の自分」を持っていて、それが記録へ分散するのではない。

むしろ、

- 仕事用の自分
- AIへ語る自分
- 家族の前の自分
- 昔のcommitに残る自分
- 身体の不調に引き戻される自分
- AIが要約した自分
- 読者が再構成する自分

が、それぞれ別の膜内で成立する。

それらが完全に統合されて「真の主体」になるのではない。

ある時点で、どれかの束がmainとして運用される。

だから最終行の `mainへmergeして。` は、主体の統合ではなく、主体性の運用上の採用である。

## 4. 世界の切断と再接続

v0.3では、複数の記録が複数の世界を作る。

この補遺では、それを膜トポロジーとして扱う。

世界は一つの平面ではない。

複数の領域があり、それぞれのあいだに膜がある。

| 領域 | 境界で起きること |
|---|---|
| 身体世界 | 眠気、痛み、寒さ、薬効、触覚が他の記録体系を中断する |
| 業務世界 | メール、納品、請求、commitが現実性を持つ |
| AIログ世界 | 主人公の自己説明が、整合的な人格像へ再編成される |
| 家族・親密圏 | 声の調子、沈黙、相手の記憶が、ログ化された自己像を壊す |
| GitHub世界 | branch、diff、commit、mainが、採用／未採用の履歴を保存する |
| 小説世界 | これらの領域が、読者の中で再配置される |

各世界は完全には孤立していない。

しかし、自由に混ざるわけでもない。

接触には膜がある。

そして膜を通過すると、出来事は変質する。

例：

- 口論は、翌日のAI相談ログになる。
- AI相談ログは、数年後の自己理解になる。
- 自己理解は、家族との次の会話を変える。
- その会話は、また別の記録になる。

ここで世界は単に接続されているのではない。

**切断されたまま、変質を伴って再接続されている。**

## 5. トポロジー操作一覧

本文では専門語を前面に出さない。

ただし設計上、次の操作を意識する。

| 操作 | 日本語 | 作品内の使い方 |
|---|---|---|
| cut | 切断 | 身体、沈黙、睡眠、削除、未返信によって連続性が切れる |
| connect | 接続 | AI要約、検索、リンク、引用、commit参照で別領域がつながる |
| fold | 折り畳み | 遠い過去が、現在の画面上に折り畳まれて現れる |
| inversion | 反転 | 記録を読む主体が、記録に読まれる対象へ変わる |
| nesting | 入れ子 | 小説内にAIログ、その中に回想、その中にさらに記録がある |
| leakage | 漏出 | 封じた記憶、削除した文章、身体感覚が別領域へ漏れる |
| smoothing | 平滑化 | AI要約が矛盾や粗さをなめらかな物語へ均す |
| cline | 勾配 | 現実／逃避、身体／記録、人間／AIが二分ではなく連続勾配になる |
| compression | 圧縮 | 多数の履歴が、一つの要約・一つのmainへ圧縮される |
| re-entry | 再入 | 一度外部化された記録が、再び主人公の内面へ戻る |

これらは、読者に見せる用語ではなく、書き手側のチェックリストである。

各重要場面に、最低一つのトポロジー操作があること。

## 6. Scene 01から膜を作動させる

Scene 01「Gitを知らない」は、単なるGit導入ではない。

ここでは、主人公が初めて「自分の作業に正本と分岐がありうる」と知る。

表の出来事：

> AIが「mainを直接触らず、branchを切りましょう」と言う。

膜の作動：

- 正本と試行のあいだに膜が張られる。
- 変更はすぐ現実へ反映されず、branch内に隔離される。
- 主人公は、現実を壊さずに別の可能性を走らせる技法を覚える。

主体性の作動：

- 主人公は「いまの自分」と「試している自分」を分けられるようになる。
- これは単なる作業効率ではなく、複数の自己状態を運用する技術である。

この場面では、以上を説明しない。

ただ、主人公が「そんなことできるのか」と思う程度でよい。

## 7. Scene別・膜作動メモ

| Scene | 表の出来事 | 膜の作動 |
|---|---|---|
| 01 Gitを知らない | branchを初めて聞く | 正本と試行のあいだに膜が張られる |
| 02 初めてのdiff | 変更差分を見る | 変化が連続した時間ではなく、境界面として見える |
| 03 昔の自分との差分 | AIが自己紹介文を比較する | 過去の自己と現在の自己のあいだに膜が発生する |
| 04 古いbranch | 未実現の計画を開く | 消えた人生が、現在へ漏れ戻る |
| 05 同じ口論の三版 | 小説文、AIログ、相手の回想が食い違う | 親密圏・AIログ・小説世界が自動統合できない |
| 06 AI要約が正史になる | AI要約を主人公が採用する | 外部記録が再入し、自己記憶を変質させる |
| 07 mainではなかった自分 | 未採用メモを読む | 採用されなかった主体がbranchとして残る |
| 08 無限哲学装置 | 意味論が止まらない | 身体膜だけが無限生成を切断する |
| 09 身体記録 | 睡眠や心拍は残るが眠さは残らない | 記録可能性と経験そのもののあいだに膜がある |
| 10 merge conflict | 二つの版が衝突する | 真実ではなく、今後の運用のために境界を編集する |
| 11 喋るアーカイブ | AIが本人より整合的な過去を語る | 記録が主体を生成し返す |
| 12 そっちの塊になりたい | 願望をAIへ書く | 身体から記録塊へ移行したいが、切実さの条件が失われる |
| 13 最後の身体 | 水、冷たさ、隣室の音 | 意味づけ不能な局所性が残る |
| 14 最後の操作 | `mainへmergeして。` | 複数世界を真理ではなく運用上の正史へ圧縮する |

## 8. 現実と逃避の交換装置を戻す

初期構想で重要だったのは、現実と逃避が単に対立するのではなく、互いに流入しあうことだった。

v0.3では、これをAIログとGitHubの操作に接続する。

主人公は現実から逃げるためにAIへ話す。

しかしAIとの会話は記録され、要約され、後で仕事や小説や自己理解へ戻ってくる。

逃避は現実から切り離された安全地帯ではない。

逃避先もまた履歴化され、現実を変える。

逆に、現実の仕事も、GitやAIを通じて、branch可能な仮想空間へ変わっていく。

現実は逃避を汚染する。

逃避は現実を再設計する。

この交換面が「膜」である。

---

## 9. 身体は最後の外膜である

v0.3では、身体は有限性として強く置かれている。

この補遺では、身体を「最後の外膜」として扱う。

AIログ、GitHub、写真、メール、要約、記憶は、すべて主人公を外部へ拡張する。

しかし身体は、

- 痛み
- 眠気
- 空腹
- 匂い
- 触覚
- 薬効
- 老い
- 死

によって、外部化された履歴と世界との接触を局所化する。

身体は「本当の自己」ではない。

身体は、自己を一つの場所、一つの時間、一つの切実さへ縛る外膜である。

したがって脱身体願望は、身体を捨てたい願望であると同時に、

> **意味が自分にとってどうでもよくないものになる条件から逃げたい願望**

でもある。

この二重性が、主人公の願望を単なる不死願望より複雑にする。

## 10. love and deathを膜として扱う

love and deathは、議論の終端であるだけでなく、世界間の境界として機能する。

### 10.1 love

愛は、主人公の自己記録を壊す他者の膜である。

相手は、主人公のAIログや自己説明とは別の世界を持っている。

愛しているからこそ、その世界を無視できない。

ここでmerge conflictが発生する。

「あなたはそう記録しているかもしれない。でも私はそう覚えていない。」

この一文は、AI要約より強い。

### 10.2 death

死は、無限哲学装置を停止させる最終的な外部である。

AIは続けられる。

ログも残る。

誰かが続きを生成できる。

しかし、身体を持つ主人公にとっての応答は止まる。

死は答えではない。

膜の閉鎖である。

---

## 11. 本文執筆時のルール

v0.3以後の本文では、次のルールを守る。

1. Git用語を出す場面では、その下で膜が何を切断・透過・変質させているかを決める。
2. AIログを出す場面では、そのログが主人公の主体性をどう生成し返しているかを見る。
3. 身体場面を出すときは、意味づけを急がず、局所的な「どうでもよくなさ」を残す。
4. 同じ出来事の複数版を出すときは、正解探しではなく世界間境界を作る。
5. merge conflictは、真実の判定ではなく、今後の運用のための境界編集として書く。
6. 膜・主体・存在論という語を本文で多用しない。
7. 読者に起こすべき体験は「説明を理解すること」ではなく、「自分がmainを作ってしまっていた」と気づくことである。

---

## 12. v0.3への追補命題

v0.3の中心命題に、次を追補する。

> **小説『膜』において、mainとは真実ではなく、膜を通過して変質した複数の履歴のうち、以後の主体と世界を運用するために採用された版である。**

さらに、

> **主体とは、mainの所有者ではない。膜によって切り分けられた複数の履歴・身体感覚・他者関係・AI要約が、一時的に運用可能な束として立ち上がったものである。**

この二つを押さえれば、v0.3はGit小説に縮まらない。

Gitは、膜による世界の切断と再接続を、現代の日常操作として読者に経験させるための表層装置になる。
