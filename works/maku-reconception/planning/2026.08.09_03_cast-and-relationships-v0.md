この文書は、人物を増やすための名簿ではなく、主人公のログ化された自己像を壊す他者を管理するための台帳である。

## 人物機能

| 枠 | 役割 | 確定度 |
|---|---|---|
| 主人公 | AI、Git、記録、身体のあいだで分散していく人物 | 高 |
| 配偶者／パートナー候補 | 主人公の自己記録とは別の記憶を持つ親密な他者 | 中 |
| 子ども候補 | 身体的生活、予定、声、世代差を通じて主人公を現在へ戻す | 低 |
| 高齢の親候補 | 過去、家族史、死、記録されない記憶を呼び込む | 低 |
| 仕事相手 | メール、納品、請求、責任の世界を成立させる | 中 |
| AI | 喋り出したアーカイブ。主人公の過去を整合的に返す | 高 |
| 過去の主人公 | 古いcommit、メモ、メール、AIログに残る別の主体 | 高 |
| 読者 | 複数版を読んで、どれをmainとして扱うかを迫られる外部主体 | 高 |

## 関係の原則

- 他者は、主人公の内面を説明するためではなく、主人公の記録と衝突するために置く。
- 親密な他者は、AI要約より短い一言で主人公の正史を揺らす。
- 仕事相手は、抽象的な思想を現実の期限、金額、納品、責任へ戻す。
- AIは登場人物でありながら、単一の人格ではなく、媒体、履歴、返答生成の束として扱う。
- 過去の主人公は、回想ではなく、参照可能なbranchとして現れる。

## 主要な衝突候補

| 衝突 | 場面の種 |
|---|---|
| 主人公 vs AI要約 | AIが本人より整合的に過去を語る |
| 主人公 vs 親密な他者 | 「あなたはそう記録しているかもしれない。でも私はそう覚えていない」 |
| 主人公 vs 仕事相手 | 記録上は完了しているが、相手の現実では終わっていない |
| 主人公 vs 過去の主人公 | 古いbranchに、今なら採用しない願望や判断が残っている |
| 主人公 vs 身体 | 文章生成は続くが、眠気、痛み、寒さが作業を止める |
