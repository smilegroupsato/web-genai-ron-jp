# Context Engineering Review｜執筆・読解方針

- ページ作成日時：2026-07-31 08:00 JST
- 最終更新日時：2026-07-31 08:00 JST

## 1. 成果物の性格

本プロジェクトは、論文紹介、要約、翻訳のいずれか単独ではなく、次を統合した専門家向けWeb原稿を作る。

1. 原論文の正確な読解
2. 用語と技術的背景の解説
3. 関連研究上の位置づけ
4. 主張・分類・根拠に対する批判的検討
5. 実システムへ適用可能な設計パターンへの一般化

## 2. 公開版と非公開情報の境界

公開版では、読者が知らない内部プロジェクト名や固有の運用語彙を論証の前提にしない。

内部実践から得た知見を扱う場合は、次のいずれかに変換する。

- 一般化した問題設定
- 再利用可能な設計パターン
- 匿名化した運用例
- 比較可能なシステム要件
- 検証可能な仮説

内部固有の名称、構成、未公開情報との対応表は公開原稿から分離する。

## 3. 読解単位

論文を節単位で精読し、各節について次を記録する。

1. 節の役割
2. 中心命題
3. 定義と分類
4. 根拠として参照される研究
5. 暗黙の前提
6. 技術的・概念的な貢献
7. 見落とし、曖昧さ、分類上の問題
8. 実装・運用への含意
9. 公開原稿へ採用する内容

## 4. 公開原稿の標準構成

- 概要
- 論文の問題設定
- 主要概念の精密な説明
- 論文全体の分類体系
- 各技術領域の読解
- 関連研究との比較
- 批判的レビュー
- 一般化した設計上の示唆
- 今後の研究課題
- 参考文献

## 5. 引用方針

- 原文引用は論点の確認に必要な最小限にする。
- 引用、要約、執筆者による解釈を明確に区別する。
- 二次資料だけで原論文の主張を確定しない。
- 書誌情報、節番号、図表番号、参照文献番号を可能な限り記録する。
- 公開時には著作権上必要な範囲を超える逐語訳を掲載しない。

## 6. 評価軸

本論文を次の軸で評価する。

- 用語定義の明確性
- 分類体系の網羅性と相互排他性
- Prompt Engineering、RAG、Memory、Tool Use、Agent Systemsとの境界
- Contextの生成・選択・圧縮・更新・廃棄を扱うライフサイクルの有無
- 推論時コンテキストと永続的知識の区別
- 単一エージェントと複数エージェントでの文脈管理の差
- ベンチマークと評価方法の妥当性
- 実システム運用への接続可能性
- セキュリティ、権限、来歴、責任主体の扱い

## 7. 初期論点

精読前の作業仮説として、次を検証する。

- Context EngineeringはPrompt Engineeringの単なる言い換えではなく、推論時にモデルへ供給される情報環境全体の設計として定義できるか。
- RAG、Memory、Tool Use、Agent Planningを単一の傘概念で統合することに、説明上・実装上の利益があるか。
- サーベイの分類は、コンテキストの「情報源」と「処理操作」と「ライフサイクル」を混同していないか。
- 文脈の正確性、鮮度、権限、来歴、コストを統合的に扱えているか。
- 個別技術の列挙を超えた、システム設計原理を提示できているか。
