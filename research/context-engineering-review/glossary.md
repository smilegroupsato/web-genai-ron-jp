# Context Engineering Review｜Glossary

- ページ作成日時：2026-07-31 08:00 JST
- 最終更新日時：2026-07-31 08:00 JST

## Context

LLMがある推論・生成を行う際に参照可能な情報の総体。単なるユーザー入力だけでなく、システム指示、会話履歴、検索結果、ツール出力、記憶、状態、メタデータなどを含み得る。原論文における定義を確認後、必要に応じて改訂する。

## Context Engineering

目的に適したモデル挙動を得るため、推論時に利用される情報環境を設計・構成・選択・更新・評価する実践および研究領域。現時点では作業定義であり、原論文の定義との差分を精読時に明記する。

## Prompt Engineering

モデルへ与える指示文や例示の設計を中心とする技法群。Context Engineeringとの包含関係、境界、歴史的位置づけは本レビューの主要検討対象とする。

## Retrieval-Augmented Generation（RAG）

外部情報源から関連情報を検索し、その結果をモデル入力へ追加して生成を補助する構成。検索、ランキング、コンテキスト構成、生成、評価を含むシステムとして扱う。

## Long Context

モデルが一度の推論で扱える長い入力文脈、またはそれを活用する技術領域。長い文脈窓そのものと、必要情報を適切に配置・選択する設計は区別する。

## Memory

会話や作業をまたいで再利用される情報・状態を保持する機構。モデル内部の学習済み知識、推論時の一時状態、外部永続ストアを混同しないことが重要である。

## Context Selection

候補情報から、現在の目的に必要な情報を選ぶ操作。検索だけでなく、除外、優先順位付け、重複除去、権限制御を含み得る。

## Context Compression

意味上重要な情報を保ちながら、モデルへ渡す情報量を削減する操作。要約、抽出、構造化、参照化などを含む。

## Provenance

コンテキストがどこから取得され、誰が作成・更新し、どの処理を経たかという来歴情報。
