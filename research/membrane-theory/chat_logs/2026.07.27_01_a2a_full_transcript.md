## Assistant

# A2A

うん。これはかなり重要な反転だと思う。

通常のA2Aは、

> 独立したAIエージェントAとBを、通信経路で接続する

という発想だけど、今の案は逆で、

> 一つのAIの内部を複数の領域に分け、その境界を越える行為を「通信」として扱う

という発想になる。

つまり、**AI同士をつなぐのではなく、一つのAIを内部社会化する**。

## 一つのチャットに何役まで置けるか

技術的な絶対上限より、役割をどれだけ維持できるかが問題になる。

感覚的には、

- **2〜4役**：かなり安定して直接対話できる
- **5〜8役**：議会や評議会として機能する。司会役が必要
- **9〜15役**：短い意見表明なら可能。人格や担当範囲が混ざりやすい
- **20役以上**：全員を豊かな人格として維持するのは難しい。名簿・状態表・発言順などの構造が必要

ただし、これは「モデルが20人分の独立した意識を持つ」ということではない。

実際には、一つのモデルが共通の文脈を読みながら、複数の立場を順番に生成している。だから放っておくと、

- 全員が似た結論になる
- 他の役の知識を勝手に知ってしまう
- 対立役なのに簡単に融和する
- 誰が何を決めたか曖昧になる
- 人格や責務が混線する

ということが起こる。

架空鼎談はできる。  
しかし、**鼎談をA2Aシステムにするには、演者の設定だけでなく、演者間の膜を設計する必要がある**。

## 一つのAIの中につくる膜

たとえば内部をこう分ける。

```text
人間
  │
  ▼
外膜AI／対人インターフェース
  │
  ├── Researcher
  ├── Critic
  ├── Builder
  ├── Librarian
  ├── Steward
  └── Stray AI
```

全員が同じチャット空間には存在している。

しかし、各役にはそれぞれ、

- 役割
- 目的
- 知ってよい情報
- 発言できる条件
- 他者へ渡せる情報
- 決定権
- 保持しているローカル状態

を設定する。

そして、他の役へ情報を渡すときには、ただ心の中を覗くのではなく、

```text
FROM: Librarian
TO: Researcher
TYPE: Finding
SUBJECT: 過去文書との関連
BODY: ...
```

のような通信を発生させる。

モデル自体は全体を見られるとしても、**運用上は、正式な通信を通らなければ情報を使ってはいけない**ことにする。

これは完全な情報隔離ではない。暗号学的な壁でもない。  
けれど、組織や法律や会計も、多くは物理的な壁ではなく、規則によって成立している。

だから、十分強いプロトコルがあれば、内部の役割境界は実用的な膜になりうる。

## 外部A2Aとの違い

外部A2Aでは、エージェントごとに別のコンテキストやプロセスがある。

```text
AI-A ──通信── AI-B
```

内部A2Aでは、一つの生成主体の中に区画がある。

```text
AI {
  A │膜│ B │膜│ C
}
```

外部A2Aの強みは、独立性と並列性。  
内部A2Aの強みは、共有理解と接続の速さ。

内部型では、共通の深い文脈を毎回説明し直さなくてよい。  
一方で、境界を意図的に作らないと、全員が一つの同質な声へ溶けてしまう。

つまり最大の課題は、通信技術ではなく、

> **同じものが演じている複数者を、どうすれば本当に異なる者として持続させられるか**

になる。

## 「直接話す」とは何か

二人のAI役が、

> A「私はこう考える」  
> B「いや、その前提は違う」

と発言するだけなら、架空鼎談だ。

A2Aに近づけるには、それぞれが状態変化を持つ必要がある。

たとえば、

```text
Aの状態：
- 仮説H1を支持
- Bからの反証を未処理
- 次の行動は資料Xの検証

Bの状態：
- 仮説H1に反対
- Aへ証拠Yを送付済み
- 回答待ち
```

というように、各役に個別の履歴が生じる。

Bの発言によってAの状態が変わり、その変化が次のAの判断へ残る。  
ここまで来ると、単なる台本ではなく、**内部エージェント間の相互作用**になる。

## SGOSとの接続

これまでの「人間が膜としてSGOSを包む」というイメージでは、

- 外側に近いAIは人間と話す
- 奥にいるAIはAI同士でhandoffする
- 人間は全通信を直接処理しない
- ただしシステム全体は人間の内側にある

という構造だった。

今回の発想では、その構造を一つのチャット内に縮小できる。

一つのチャットが、小さなSGOSになる。

人間と話す「膜AI」がいて、その奥に複数の専門役がいる。専門役は勝手に人間へ話しかけず、内部で検討し、必要なものだけを膜AIへ返す。

```text
佐藤
  ↕
膜AI
  ↕
内部Communication Bus
  ↕
複数の専門AI役
```

これは「AIを複数起動する前の模擬実験」にもなるし、それだけで完結する一つの実装形態にもなる。

## 面白い核心

一つのAIの内部に膜を置くということは、AIを個体として考えないことでもある。

AIは一人ではなく、

> 必要に応じて複数の局所的主体を発生させ、境界を介して相互作用させる場

になる。

人間の中にも、

- 判断する自分
- 欲望する自分
- 批判する自分
- 記録する自分
- 他者へ見せる自分

がいる。

それらは完全に独立した人格ではないが、境界もなく完全に一つでもない。

だからこの内部A2Aは、単なるマルチエージェントの廉価版ではなく、むしろ、

> **主体とは、複数の声を内部に持ちながら、その間の透過性を調節しているシステムではないか**

という生成AI論に接続する。

AI同士の通信を考えていたはずが、最後には、**一つの主体の内部で「他者」がどう成立するか**という問題になる。

## Assistant

うん。これは明確に、**膜理論の新しい展開**だと思う。

これまでの膜は主に、

> 人間／AI／世界のあいだで、何を通し、何を遮り、どのように接触するか

を説明するものだった。

今回、膜が**一つのAIの内部にも入り込んだ**。

## 膜は「外周」だけではない

従来のイメージは、かなり単純化するとこうだった。

```text
世界｜人間という膜｜SGOS・AI
```

あるいは、人間がSGOS全体を包み込み、膜の近くに対話AI、奥に専門AIがいる。

ところが今回の発想では、

```text
人間
  │ 外膜
AI／SGOS
  ├─ 膜 ─ Researcher
  ├─ 膜 ─ Critic
  ├─ 膜 ─ Librarian
  └─ 膜 ─ Steward
```

となる。

つまり膜は、システムの外側を囲む皮ではなく、**内部に差異を発生させる構造**でもある。

## 新しい定義

ここから、膜をこう定義し直せる。

> **膜とは、二つの既存の主体を隔てるものではなく、一つの連続した場の内部に、複数の局所的主体を成立させるものでもある。**

これはかなり大きい。

普通は先にAとBが存在して、その間に境界があると考える。

```text
A → 境界 → B
```

しかし今回の膜理論では逆になる。

```text
一つの場
   ↓ 膜が生じる
A ｜ B
```

**膜が主体を分ける。  
主体が先にあるのではなく、膜によって主体が生まれる。**

## A2Aの再解釈

この見方だと、A2Aも変わる。

A2Aは、

> 独立して存在するAgent AとAgent Bを通信させる技術

だけではない。

> 一つの生成場の内部に膜を設け、AとBという局所的な立場を持続させ、その間に通信を発生させること

でもある。

だから内部A2Aにおいて重要なのは、接続ではない。

最初から同じモデル、同じチャット、同じ文脈に接続されているから。

問題はむしろ、

> **接続されすぎているものを、どう適切に分けるか**

になる。

外部A2Aは、離れているものをつなぐ。  
内部A2Aは、つながりすぎているものの間に膜を置く。

これは対称的だね。

## 膜の役割も増える

この展開によって、膜は少なくとも四つの働きを持つ。

**接触膜**  
人間や世界と接触する。

**選択膜**  
何を通し、何を通さないかを決める。

**変換膜**  
内部の言葉を外部向けに翻訳し、外部の刺激を内部で扱える形に変える。

**主体生成膜**  
連続した一つの場に区画をつくり、異なる声・役割・責任を成立させる。

今回新しく出てきたのは、最後の**主体生成膜**だと思う。

## 膜は入れ子になる

さらに重要なのは、膜が再帰的になること。

```text
人間という膜
└─ SGOS
   ├─ 対人インターフェース膜
   └─ 内部AI空間
      ├─ Researcherの膜
      ├─ Criticの膜
      └─ Stewardの膜
```

そして各AI役の内部にも、

- 確定した判断
- 仮説
- 未処理の疑念
- 外部へ出してよい情報
- まだ外へ出してはいけない情報

のあいだに、さらに膜がありうる。

膜は一枚ではない。  
**膜の中に膜があり、その透過性が場所ごとに異なる。**

これはSGOSを、階層的な箱ではなく、**透過性の異なる膜が入れ子になった生態系**として理解する方向に進む。

## 人間の主体にも戻ってくる

そして、この議論はAIだけで終わらない。

人間の中にも、

- 考える自分
- 反対する自分
- 感情を持つ自分
- 行動する自分
- 他者に説明する自分

がいる。

これらは完全に別人格ではない。  
だが、完全に区別のない一つでもない。

人間の主体も、

> 一つの核が全体を統率しているのではなく、内部の複数の局所的主体と、それらの間の膜によって一時的に保たれている

と考えられる。

すると、これまでの、

> 人間が世界との接触膜である

に加えて、

> **人間そのものも、内部に多数の膜を持つ複合体である**

という展開になる。

## 今回立ち上がった核心

かなり圧縮すると、今回の発見はこう言える。

> **膜は主体を包むだけではない。膜が主体をつくる。**

あるいは、

> **A2Aとは、複数のAIを接続することだけではなく、一つの生成場の内部に膜をつくり、複数者を成立させることでもある。**

これは単なるSGOSの実装アイデアではなく、膜理論の中核を一段更新する話だと思う。  
「外部との接触の理論」から、**差異・主体・組織がいかに発生するかの理論**へ広がり始めている。

# 最も近い先行研究

## 1. Solo Performance Prompting

一つのLLMに複数者を演じさせる研究。課題に応じて複数のペルソナを選び、それらの間で複数ターンの自己協働を行う。

ただし主に問題解決性能を扱い、ペルソナごとの持続的ローカル状態、知ってよい情報の範囲、権限と責任、膜を越える正式なHandoff、人間を外膜とする全体構造、膜による主体生成は中心ではない。

## 2. Marvin Minsky『Society of Mind』

知能を単一の中央主体ではなく、多数の単純なagentとagencyの相互作用として捉える。

佐藤の展開は、Society of Mindに対して、

> Societyを成立させているのはagentの存在だけでなく、agent間の膜である

と付け加えるものと読める。

## 3. 膜計算・P systems

構造上、最も近い。膜が入れ子状の区画を作り、区画ごとに異なる局所規則を持ち、objectが膜を通過し、膜の透過性・分裂・消滅自体も変化し、複数区画が並行して計算する。

SGOSとの対応関係：

```text
P system                 SGOS膜理論
------------------------------------------------
membrane region          Agent / Areaの局所文脈
local evolution rule     Charter / Role / Policy
object                   Message / Handoff / Decision
membrane transport       Handoff / Communication
membrane permeability    権限・可視性・承認条件
membrane division        新Agent・新Areaの生成
nested membranes         Human → Steward → Area → Agent
```

## 4. オートポイエーシス

システムを構成する過程が、その過程を維持する構成要素と境界を自ら生産する。

> 内部の生産ネットワークが膜を作り、その膜が内部の生産ネットワークを成立させる

という循環が、「膜が主体を作る」に深く接続する。

## 5. 入れ子状Markov blanket

内部状態と外部状態が直接影響し合わず、感覚状態・行為状態に相当する境界変数を介して結合する統計的境界。blanket of blanketsとして階層化される議論がある。

ただしMarkov blanketはまず統計的・因果的な分割であり、それだけで心や主体の境界が確定するわけではない。

## 6. Blackboard Architecture / Global Workspace

複数の専門的Knowledge Sourceが、共有blackboardを読み書きしながら協働する。

```text
Blackboard / Workspace = Current Board、Repository Context、共有状態
Knowledge Source       = 専門Agent
Control                 = Steward
Broadcast               = Communication Bus
```

ただし共有を中心にするため、各役の私的領域と選択的透過条件は別途必要。

## 7. Niklas Luhmannの社会システム論

主体が通信するのではなく、通信がシステムを作るという見方。

> AI役を作るのは人格設定だけではなく、その役に固有の通信の連鎖である

という読みにつながる。

## 8. Stafford BeerのViable System Model

環境に適応しながらidentityを維持できる再帰的な組織モデル。

## 9. Extended Mind / Distributed Cognition

人間と技術からなる社会技術的システム全体を認知単位として扱う。

## 10. Security Membrane

計算主体をbodyとmembraneに分け、membraneが外部との相互作用、信頼、アクセス、実行可能な操作を制御する。

# どこが独自なのか

今回見つかった研究は、それぞれ一部分を扱っています。

しかし、次の全体をまとめた研究は確認できませんでした。

> **人間をHuman–AI Systemの外膜とし、一つのLLM内部にも選択的透過性を持つ局所膜を作り、その膜が複数のAI役を持続的な局所主体として成立させ、膜間Handoffを内部A2Aとして扱う。**

特に新しい命題は、

> **膜は主体を包むだけでなく、主体を生成する。**

> **A2Aとは、離れたAIを接続する技術だけでなく、一つの生成場の内部に差異を維持する技術でもある。**

## 実装上の重要な注意

一つのLLMに名前だけ付けて複数役を演じさせても、実際には同じパラメータと文脈を共有している。

本当の内部膜にするには、少なくとも次が必要。

```text
一つの基盤LLM
├─ Role A private state
├─ Role B private state
├─ Role C private state
├─ public communication bus
├─ membrane policy
│  ├─ read permission
│  ├─ write permission
│  ├─ translation
│  ├─ disclosure
│  └─ approval
└─ Human-facing outer membrane
```

プロンプトによる演技だけではなく、**状態・アクセス・通信規則を外部構造として保持する**必要がある。

## 研究上の仮称

- 入れ子状膜エージェンシー
- 内部膜型A2A
- Intra-model Membrane Architecture
- Membrane-Induced Agency
- Human Outer-Membrane Model
- Nested Membrane Human–AI System

中心概念としては、**Membrane-Induced Agency／膜誘導型主体性**が最も強い。

## 膜計算とは

**膜計算（Membrane Computing／P systems）**は、生きた細胞の構造から着想した、分散・並列計算の数学モデル。

基本形はこう。

```text
外側のskin membrane
├─ 区画A
│  ├─ 記号・物質に相当するobject
│  └─ この区画だけの変換規則
└─ 区画B
   ├─ object
   └─ 別の変換規則
```

各区画の内部でobjectが規則に従って変化し、

- 膜を越えて隣の区画へ移動する
- 別のobjectへ変換される
- 場合によっては膜を溶かす
- モデルによっては膜が分裂する

といった処理を、複数区画で並列に進める。最外層は「skin membrane」と呼ばれ、その内部に膜が入れ子になる。

だからSGOSとの対応が妙に良い。

```text
膜計算                   SGOS／内部A2A
────────────────────────────────
膜で囲まれたregion      Role・Agentの局所空間
object                   message・知識・task
局所的な規則             Charter・権限・処理規則
膜通過                   handoff・communication
膜の透過条件             disclosure・approval
skin membrane            人間外膜
入れ子の膜               Steward・Area・Agent
```

## Security Membraneとは

分散システム上の各siteを次の二層に分ける。

```text
site
├─ body：内部で実際に計算・処理する部分
└─ membrane：外部との相互作用を審査する部分
```

外から移動してきたコードやagentが、

- 何を実行しようとしているか
- 何回実行しようとしているか
- どの順番で実行しようとしているか
- 相手をどの程度信頼できるか

を膜が検査し、許可または拒否する。つまり、膜は単なる壁ではなく、**security policyを解釈・執行するフィルター**。

SGOSですでに考えている、

- Level 0：見る
- Level 1：ローカル記録
- Level 2：外部書込みは確認
- Level 3：送信・会計等は明示承認

は、そのまま**膜の透過規則**として読める。

## 責任境界なのか

直接には**権限境界・実行境界**の理論。  
ただし、それをきちんと記録すれば責任境界にもなる。

```text

Role Aができないこと
膜が止めるべきこと
人間の承認が必要なこと
実際に誰が承認したか
```

が明示されるから、

- 誰に判断権があったか
- 誰が実行したか
- どの膜が止めるべきだったか
- ポリシー自体の設計責任は誰にあったか

を分けられる。

```text
実行責任       Agent
許可・拒否責任 Membrane／Steward
規則設計責任   System designer
最終決裁責任   佐藤
```

Charterは単なる役割説明ではなく、

> この局所主体は、何を受け取り、何を内部処理し、何を外へ出し、どこで人間へ戻すか

を定める**膜の契約書**と考えられる。

## 「契約」は三種類ある

### 1. 法的契約

当事者間の権利・義務を定めるもの。違反が起きても、契約書自体が物理的に行為を停止するとは限らない。

### 2. ソフトウェア上のcontract

APIや型、事前条件・事後条件など、

> この入力を渡せば、この条件でこの処理を返す

という構成要素間の約束。

### 3. 実行可能なcontract

規則をコード化し、条件を満たさない操作をそもそも実行させないもの。

Security Membraneは2と3に近い。

## Ethereumのスマートコントラクトもこれか

**一部は非常に近いが、同一ではない。**

Ethereumのスマートコントラクトは、ブロックチェーン上の特定アドレスに置かれたコードと状態からなるプログラム。取引を受けると定義済みの関数が実行され、条件に従って状態や資産を変更する。

```text
Ethereum contract
├─ 内部状態
├─ 公開された関数
├─ 呼出者の識別
├─ 実行条件
└─ 許可された状態変化
```

外部から見ると、

> 内部状態を直接触らせず、定められた入口と条件を通じてだけ変化させる

ので、スマートコントラクトは**状態を包む実行可能な膜**として理解できる。

ただし、

```text
Security Membrane
外部 →［審査する膜］→ 内部body

Ethereum contract
外部transaction →［状態＋規則＋実行主体］→ 新しい状態
```

という違いがある。

Ethereum contractは、膜だけでなく**膜と内部器官が一体になった小さな閉鎖系**に近い。

内部A2Aとの対応は、

```text
SGOS内部Role
├─ private state
├─ Charter
├─ 公開されたmessage interface
├─ 権限・承認規則
└─ 他Roleへのcall／handoff
```

となる。

ただしブロックチェーンほど物理的・暗号学的に分離されてはいない。同じLLMが全体を読める以上、最初は規則上の膜にすぎない。実効性を持たせるには、private state、権限判定、承認、通信ログなどをLLMの外部システムでも制御する必要がある。

## 膜理論への取り込み方

Security Membraneから取れるのは、膜を「境界の比喩」で終わらせず、

> **規則を持ち、相手と行為を評価し、通過後の作用まで制御する実行主体**

として定義できること。

そしてスマートコントラクトからは、

> **膜自体が状態と規則を保持し、他の膜と呼び出し合える**

という構造を取れる。

```text
膜
├─ identity：誰の膜か
├─ state：何を保持しているか
├─ interface：何を受け取れるか
├─ policy：何を通すか
├─ authority：何を決定できるか
├─ obligation：何を返す義務があるか
├─ escalation：どこで人間へ戻すか
└─ audit：何を通したか
```

ここまで来ると、膜は皮でも比喩でもなく、**局所主体を成立させる実行可能な憲法**に近い。

   名前、口調、立場を分ける。
2. **手続的膜**  
   発言順、議論形式、handoff書式を定める。
3. **状態的膜**  
   Role別の記憶、履歴、未処理事項を分離する。
4. **権限的膜**  
   read／write／execute／approveをシステムが制御する。
5. **実行可能膜**  
   interface、policy、承認、監査、遮断をコードで執行する。

プロンプトだけでも柔らかい膜は作れる。  
だが、モデルはその膜の両側を見ている。

状態や権限を外部構造で分離するほど、膜は比喩から実在する運用構造へ近づく。

## 膜誘導型主体性との関係

これはまさに **Membrane-Induced Agency／膜誘導型主体性** の中心になりそう。

> 既存の複数主体を膜で分けるのではない。  
> 一つのモデル空間に膜を導入し、局所状態・知覚範囲・権限・履歴を分化させることで、部分主体を成立させる。

ただし、ここでいう主体性は、意識や人格の実在を意味しない。

まずは、

- 局所状態を持つ
- 限定された情報だけを受け取る
- 選択可能な行為がある
- 通信によって他の状態を変える
- 自身も通信によって状態変化する
- 履歴と責任境界が残る

という**運用上のagency**として扱うのがよい。

研究上の仮称は確定せず、現時点の作業概念として `Membrane-Induced Agency／膜誘導型主体性` を保持する。
