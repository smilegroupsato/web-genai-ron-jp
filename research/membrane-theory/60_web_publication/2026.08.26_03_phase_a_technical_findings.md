## 確認したこと

### 1. nested source path

registryの`source`は、`content/`配下のMarkdownであれば階層制限がない。

したがって、次は許容される。

```text
content/membrane/index.md
content/membrane/about.md
content/membrane/research-map.md
content/membrane/thoughts/exchange-device.md
content/membrane/reading/<slug>.md
```

### 2. nested route

route validatorは絶対directory routeを許容しており、次は形式上通る。

```text
/membrane/
/membrane/about/
/membrane/research-map/
/membrane/thoughts/exchange-device/
/membrane/reading/<slug>/
```

candidate builderもslugから階層をそのまま生成するため、nested route自体の追加対応は不要。

### 3. canonical

production sourceでは、front matterの`canonical_url`がregistry routeと完全一致することを要求する。

例：

```text
slug: /membrane/
canonical_url: https://genai-ron.jp/membrane/
```

この契約はそのまま利用できる。

### 4. 最初の `/membrane/` のindex契約

production文書は、公開前に`index_source`と`index_html`の双方へ対象routeのリンクがちょうど1件必要。

最初の`/membrane/`では、既存のGENAI-RONトップをindexとして使う。

```text
index_source: content/index.md
index_html: site/index.html
```

両方に`/membrane/`への導線を1件置いたうえでprepareする。

`/membrane/about/`以降は、公開済みの膜トップをindexとして使う設計が可能。

公開承認前にproduction側indexだけが先行変更されないよう、index差分以降はpublication用branchで扱う。

### 5. theme

現行structured previewでは非series文書に通常のsite headerが使われる。`default-academic`はproduction-enabledであり、最初の技術通しには利用可能。

膜専用themeはPhase Aの必須条件ではない。

### 6. manifest上の対応

`build_site_manifest.py` は現在、次を正式に扱う。

```text
/membrane/                           -> content/membrane/index.md
/membrane/about/                     -> content/membrane/about.md
/membrane/research-map/              -> content/membrane/research-map.md
/membrane/thoughts/<slug>/           -> content/membrane/thoughts/<slug>.md
/membrane/reading/<slug>/            -> content/membrane/reading/<slug>.md
/membrane/bibliography/              -> content/membrane/bibliography.md
```

page typeは次のとおり。

```text
/membrane/       -> membrane-index
/membrane/.../   -> membrane-entry
```

出版基盤側ではmanifest build / `--check`、publication fixture、拒否条件、semantic parity、desktop/mobile visual QAまで成功が報告されている。
