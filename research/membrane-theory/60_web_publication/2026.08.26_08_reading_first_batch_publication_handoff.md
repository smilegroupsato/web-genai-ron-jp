## 4. Editorial boundary

各完成稿は次の区別を維持する。

### 文献そのものについて

- 書誌
- この文献は何をしたか
- 重要概念
- 歴史的位置
- 限界・注意

### MEMBRANE側の読み

節名：

**ここから先は私の読解**

この節では、生物膜研究から別領域を考えるための構造的な問いを抽出する。

生体膜の具体的な分子機構が心理・社会・AIにそのまま存在すると主張しない。

この境界は公開時にも保持すること。

## 5. Publication metadata方針

新規文書公開レーン側でproduction用Markdownへ移植するときは、現行MEMBRANE publication規約に従って必須metadataを付与する。

想定：

- collection / namespace：`membrane`
- section：`reading`
- theme：`membrane-academic`
- status：publication-candidate
- canonical URL：各proposed routeに対応した `https://genai-ron.jp/...`

正確なmetadata key、route registry、candidate / receipt / deploy処理は公開レーン側の現行正本を優先する。

本Handoffはpublication基盤内部仕様を固定しない。

## 6. 公開本文に含めないもの

public editionに記録用として存在する以下のメタ情報は、公開ページ本文に露出させない。

- ページ作成日時
- 最終更新日時
- status
- source note path
- bibliography_idの内部管理表示
- proposed routeの内部管理表示
- 更新履歴
- 内部repository path

ただし、Web上の公開日・最終更新日をpublication基盤の標準表示として出す場合は、その正規仕様に従う。

## 7. Cross-link希望

公開時に可能なら以下の相互導線を設定する。

- R1 → 次に読む：R2
- R2 → 前：R1 / 次：R3
- R3 → 前：R2
- 3本すべて → `/membrane/`
- 3本すべて → 将来の `/membrane/bibliography/`

未公開routeへのリンクは生成しない。

## 9. Handoff判定

3本とも **内容確定 / publication Handoff可**。

以後、誤記・書誌上の問題・publication QAで発見された問題を除き、公開作業中に内容を大きく書き換えない。

大きな内容変更が必要になった場合は、MEMBRANE作成側へ戻してpublic editionを更新する。

## 10. 新規文書公開レーンへの依頼

この3本をReading第1陣として受領し、公開レーンの現行正本に従って、production用Markdown化から公開確認まで進めてください。

公開順は原則として R1 → R2 → R3。

3本を同一publication batchとして扱える場合は一括で進めてよい。

MEMBRANE作成側への確認が必要なのは、本文内容・タイトル・公開上の意味に変更が生じる場合のみとする。
