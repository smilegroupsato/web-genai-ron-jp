# P systemsとSGOS膜構想｜章横断比較ノート

## 0. 目的

本ページは、『A Guide to Membrane Computing』の章別読解から生まれたSGOS側の論点を集約する。

原著の説明を再掲する場所ではなく、章をまたいで比較可能な仮説、非対応、設計上の問いを保持する場所である。

## 1. 現時点の中心命題

P systemsの膜は、SGOSの膜構想にとって有力な先行モデルである。ただし、両者は同一ではない。

P systemsからSGOSが学べるのは、膜を次の統合構造として形式化する発想である。

- 区画化
- 局所状態
- 局所規則
- 選択的透過
- 宛先付き通信
- 境界状態の変化
- 複数区画による並列計算

一方、SGOS側には次の追加問題がある。

- 記号ではなく意味を扱う
- 人間とAIが相互解釈する
- 非同期に進む
- Source of Truthが複数媒体に分散する
- 境界と規則そのものを対話で変更する
- 責任、承認、権限、監査が必要である
- 長期のRepository Contextを維持する

## 2. 暫定対応表

| P systems | SGOS候補 | 注意 |
| --- | --- | --- |
| membrane | context / responsibility boundary | 防壁だけでなく通信制御を含む |
| region | Agent Area / 専門チャット / Repository責務領域 | SGOSでは領域が重なりうる |
| object | message / task / artifact / context fragment | 意味と参照関係を落とせない |
| multiset | 利用可能な情報・資源の量的状態 | 重複が単なる個数とは限らない |
| evolution rule | workflow / procedure / agent rule | 人間判断で上書きされうる |
| catalyst | prompt / schema / policy / tool | SGOSでは触媒も更新される |
| `in_j` | 宛先指定handoff | routingと受領条件が必要 |
| `out` | return handoff / escalation / external write | 外部書込には承認が必要 |
| `here` | local state retention | 原本か一時状態かを区別する |
| permeability | access / approval / disclosure policy | 対象・方向・状態ごとに異なる |

## 4. Communication / Handoff / Context Syncの再配置

### Communication

膜を通過する対象と経路の全体設計。

### Handoff

あるregionの局所状態を、受信regionで作用可能なmessage / artifactへ変換して通過させる具体的な膜作用。

### Context Sync

複数regionの全状態を常時一致させる処理ではない。必要な状態差分を、必要な時点と粒度で、選択的に通過させる整合回復作用。

### Steward

個別region内部の処理者ではなく、膜間の責務衝突、透過条件、例外、境界変更を扱う統合機能として再定義できる可能性がある。

## 5. 「一つのAIの中に膜をつくる」問題

佐藤の発想は、複数AIをネットワーク接続する代わりに、一つのAI内部に役割境界を形成するものである。

この構成を膜と呼ぶためには、少なくとも次を検証する必要がある。

- 各役が別の局所contextを保持しているか
- ある役の情報が無条件に他役へ漏れないか
- 役間通信が明示的なenvelopeを通るか
- 各役に異なる規則・権限・停止条件を設定できるか
- 通信履歴と状態変化を観測できるか
- 膜を開閉・分裂・統合できるか

単に「A役として発言」「B役として発言」と交互に生成するだけなら、膜ではなく、一つのregion内で複数の話法を切り替えている可能性がある。

## 6. P systemsを参照する際の誤読防止

### 生物学的正しさを目的としない

P systems自体が、生物膜の忠実なシミュレーションではない。SGOSがP systemsを参照する際にも、「生物に似ているから正しい」という論法を使わない。

### 計算万能性を価値の中心にしない

SGOSが目指すのは、何でも計算できることではなく、人間とAIが長期的・安全・再開可能に協働することにある。

### 並列化を無条件に善としない

P systemsでは大規模並列性が効率の源泉となる。SGOSではAgent数やチャット数の増加が、context cost、監督負荷、責務衝突、記録散逸を増やす。

最大並列より、選択的並列、停止、統合、委譲の設計が重要である。

### 階層木に閉じない

基本P systemの入れ子構造は有用だが、SGOSはネットワーク型・重複所属型・時間変化型の境界を必要とする可能性が高い。

## 7. 今後の研究課題

- SGOS membrane schemaの最小実装可能版
- Communication Envelopeを「膜通過可能な対象」として再定義
- Handoff Protocolの膜モデルによる再読
- Context Syncと選択的透過性の関係整理
- Steward Charterと最外膜・境界管理の関係
- 一つのLLM内部に実効的な膜を作れる条件
- 複数Agent間の膜と、一つのAI内部の膜の比較実験
- 同期型P systemと非同期SGOSの形式差
- 意味、曖昧さ、信頼度、責任を持つobject model
- Repository Contextを長期保持するregion / environmentモデル

## 8. 現時点の評価

P systemsは、佐藤の膜構想をそのまま説明する完成理論ではない。

しかし、SGOS内で別々に育ってきた次の領域を、一つの設計語彙へ近づける力がある。

- Selective Permeability
- Communication Architecture
- Handoff Protocol
- Context Sync
- Agent Identity
- Stewardship
- Repository Context
- 一つのAI内部の複数役

P systemsを「答え」とするのではなく、SGOS膜理論を形式化するための強い比較対象として扱う。
